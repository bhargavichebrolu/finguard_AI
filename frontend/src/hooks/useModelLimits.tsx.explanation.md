# useModelLimits.tsx

Source: [frontend/src/hooks/useModelLimits.tsx](useModelLimits.tsx)

## A. File Purpose
Loads the frozen model's measured limitations once per session and shares them with every page that shows a score.

## B. Why This File Exists
The authorisation requires the interface to disclose recall and false-positive-rate limitations clearly, and the PRD forbids hardcoded statistics. The API builds these sentences from the saved Phase 2 results, and this provider fetches them once.

## C. Dependencies
- **Libraries:** React.
- **Internal modules:** `../services/endpoints.ts`, `useApiResource.ts`.
- **External services / database:** `GET /api/v1/models/metrics`.
- **Depended on by:** `App.tsx` (provider), `ScoreDisclosure.tsx` and pages.

## D. Every Function Explained

### `ModelLimitsProvider`
Loads the metrics and provides `metrics`, `notes`, `error` and `loading`. It wraps the signed-in layout, so loading starts after sign-in.

### `useModelLimits`
Returns the provided value. It throws outside the provider.

## E. Classes Explained
None.

## F. Execution Flow
After sign-in the provider requests the metrics once. Pages read the notes from context.

## G. Input and Output
Output: `performance_notes` from the API, and the full metrics for pages that chart them.

## H. Important Technical Concepts
- **No figure lives in the frontend.** The sentences, such as the one stating the test false positive rate against its target, are generated by the backend from the saved metrics file. A source-scan test fails if any of those figures appears in `src/`.

## I. Example
```ts
const { notes } = useModelLimits();
```

## J. Maintenance Notes
If the notes fail to load, `ScoreDisclosure` warns rather than hiding the problem. Keep it that way.
