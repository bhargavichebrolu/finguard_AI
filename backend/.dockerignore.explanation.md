# .dockerignore

Source: [backend/.dockerignore](.dockerignore)

## A. File Purpose
Lists files that must not be sent to Docker when building the API image.

## B. Why This File Exists
Without it, a local `.venv` containing Windows binaries, cached files, temporary uploads and any stray `.env` could enter the image. Excluding them keeps builds fast and keeps secrets and uploaded data out of image layers.

## C. Dependencies
- **Libraries / tools:** Docker.
- **Internal files:** the `backend/` folder.
- **External services / database:** none.
- **Depended on by:** `backend/Dockerfile`.

## D. Every Function Explained
No functions. The groups:

### Local environment and caches
`.venv`, `__pycache__`, `*.py[cod]`, `.pytest_cache`, `.ruff_cache` and `catboost_info`.

### Not needed at run time
`tests`, `tmp` and `*.md`, including the explanation documents beside the code. A plain pattern such as `*.md` matches only at the context root, so since Phase 6 `**/*.md`, `**/__pycache__` and `**/*.py[cod]` also exclude them inside `app/` and `migrations/`; before that, the image contained the explanation documents and any local bytecode caches.

### Secrets
`.env` and `.env.*`, as a second layer of protection. The real `.env` lives at the repository root, outside this build context.

## E. Classes Explained
None.

## F. Execution Flow
Docker reads it before copying the build context.

## G. Input and Output
Not applicable.

## H. Important Technical Concepts
- **Build context:** everything sent to Docker for a build. A secret in the context can end up in a layer, and deleting it from a later layer does not remove it.

## I. Example
```powershell
docker compose build api
```
