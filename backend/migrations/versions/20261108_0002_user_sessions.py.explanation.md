# 20261108_0002_user_sessions.py

Source: [backend/migrations/versions/20261108_0002_user_sessions.py](20261108_0002_user_sessions.py)

## A. File Purpose
Adds the `user_sessions` table, which records each browser sign-in so it can be revoked on logout.

## B. Why This File Exists
The Phase 4 authorisation requires cookie sessions with logout. A signed token alone cannot be withdrawn before it expires, so a server-side record is needed.

## C. Dependencies
- **Libraries:** `alembic`, `sqlalchemy`.
- **Internal modules:** none at run time.
- **External services / database:** PostgreSQL.
- **Depended on by:** `alembic upgrade head`, after revision `0001`.

## D. Every Function Explained

### `upgrade`
Creates `user_sessions` (id, user_id, csrf_token_hash, created_at, expires_at, revoked_at), a foreign key to `users` with `ON DELETE CASCADE`, and an index on `user_id`.

### `downgrade`
Drops the index and the table, which ends all browser sessions.

## E. Classes Explained
None.

## F. Execution Flow
Runs after `0001`. Generated by autogenerate, then reviewed.

## G. Input and Output
Input: a schema at `0001`. Output: a schema at `0002`.

## H. Important Technical Concepts
- **Only a hash of the CSRF token is stored,** so a copy of the database does not give usable tokens.
- **Additive only:** no existing table or row changes, so Phase 3 data is untouched.
